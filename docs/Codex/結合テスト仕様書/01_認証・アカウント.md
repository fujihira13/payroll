# 01 認証・アカウント 結合テスト仕様書

## 1. テスト目的

3権限のログイン入口、パスワード照合、失敗回数、ロック、利用状態、初回パスワード変更、ログアウト、セッションが連携して正しく動作することを確認します。

## 2. 対象機能

- システム管理者ログイン `/login/manage`
- 社員管理者・一般社員ログイン `/login`
- ログイン状態保持
- 5回失敗時のロック
- システム管理者・社員側パスワード変更
- ログアウト

## 3. 事前条件

- 共通テストデータの管理者・社員を準備済み
- ブラウザの通常ウィンドウとプライベートウィンドウを使用可能
- DBで失敗回数、ロック、最終ログイン日時を確認可能
- レート制限確認は他ケースへ影響しない送信元・時間帯で実施

## 5. DB確認項目

- `admins.try_count`、`lock_status`、`last_login_at`、`force_password_change`
- `users.login_failure_count`、`lock_status`、`last_login_at`、`force_password_change`
- パスワードが平文ではなくハッシュで保存されていること
- ログイン成功時に失敗回数が0へ戻ること

## 6. 現行実装上の重点確認

企業を論理削除した場合、所属企業の関連情報を通常検索で取得できず、ログイン処理の会社停止確認を通過する可能性があります。IT-AUTH-19でログインできた場合は仕様どおりとせず、情報分離に関わる不具合候補として記録します。
