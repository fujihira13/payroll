# 共通テストデータ・環境確認

## 1. 目的

11大機能のテストで共通して使用する環境、アカウント、会社、部署、帳票、CSV、証跡の基準を定めます。ケースごとに異なるデータを勝手に作ると件数や期待結果が再現できなくなるため、原則としてこの基準を使用します。

## 2. 安全上の前提

- 本番環境・本番DBでは実施しません。
- 個人の実在する氏名、メール、給与額を使用しません。
- DBを初期化する操作は、対象がテスト環境であることを確認してから行います。
- テストメールはMailpit等の外部送信されない環境を使用します。
- FAIL再現に必要なデータは、再テスト完了まで保持します。

## 3. 標準環境

| 項目 | 基準 |

| アプリURL | `http://localhost:8080` |

## 9. 共通証跡・実施記録

各ケース実施時に次を記録します。

| 項目 | 記入内容 |
|---|---|
| テストID | 仕様書のID |
| 実施日・実施者 | 日時、氏名 |
| 環境 | ブランチ、コミット、ブラウザ、DB |
| 判定 | PASS／FAIL／BLOCKED／NOT RUN／N/A |
| 実際の結果 | 画面文言、HTTP状態、件数、日時等 |
| 証跡 | 画像、CSV、PDF、メール、ログの保存先 |
| 障害番号 | FAIL時のIssue等 |

## 10. テストデータの復旧

- ロック確認後は別管理者からロックを解除します。
- 仮パスワード確認後は本人が標準パスワードへ変更します。
- 公開済み給与処理は状態を戻せないため、ケースごとに新しい対象月または名称を使用します。
- 論理削除した企業・管理者・部署・社員は画面から復元できません。削除専用データを用意します。
- Mailpitのメールはケース開始前に識別しやすい状態にし、件名へテストIDを含めることを推奨します。
