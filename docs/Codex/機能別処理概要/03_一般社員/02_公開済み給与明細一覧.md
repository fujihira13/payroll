# 公開済み給与明細一覧 — 処理概要

## 1. 目的

一般社員または社員管理者が、自分自身に公開された給与明細を一覧で確認し、詳細画面へ進む機能です。

| 項目 | 内容 |
|---|---|
| 対象 | 一般社員、社員管理者本人 |
| URL | `/employee/payslips` |
| 表示対象 | 公開済みかつ本人の明細だけ |

## 2. 一覧取得

次の条件を両方満たす明細だけを検索します。

- 明細の`employee_id`がログイン中社員のIDと一致
- 関連する給与処理の状態が「公開済み」

明細データの新しい順で12件ずつ表示します。対象月順ではなく、明細レコードの作成日時順です。

## 3. 表示項目

| 項目 | 内容 |
|---|---|
| 対象月 | 給与処理の対象月 |
| 明細名 | 給与処理名 |
| 差引支給額 | 総支給額から控除合計を引いた保存済み金額 |
| 閲覧状態 | 初回閲覧日時の有無で未閲覧・閲覧済みを表示 |
| 公開日 | 実際に自動公開された日 |
| 明細を見る | 詳細画面へのリンク |

公開明細がない場合は「公開された給与明細はまだありません」と表示します。

## 4. データへの影響

一覧を開くだけでは、初回閲覧日時・最終閲覧日時・閲覧回数を変更しません。

## 5. 安全対策

検索条件に本人IDを直接含めるため、一覧に他人の明細は混ざりません。詳細を開く際も別途本人確認と公開状態確認を行います。

## 6. 注意事項

- 対象月による検索・絞り込みはありません。
- 同じ対象月に複数の給与処理がある場合は複数行表示されます。
- 公開日には通知メール送信日ではなく、給与処理の公開日時を表示します。
- 通知メール送信に失敗しても公開済みなら一覧に表示されます。

## 7. 動作確認の観点

1. 本人の公開済み明細だけ表示すること。
2. 本人でも下書き・公開待ち明細を表示しないこと。
3. 一覧表示だけでは閲覧済みにならないこと。
4. 12件単位でページ移動できること。

## 8. 主な根拠ファイル

- `app/Http/Controllers/Employee/PayslipController.php`
- `resources/views/employee/payslips/index.blade.php`
- `app/Models/Payslip.php`
