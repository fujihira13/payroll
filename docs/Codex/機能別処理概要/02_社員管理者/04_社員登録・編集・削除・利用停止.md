# 社員登録・編集・削除・利用停止 — 処理概要

## 1. 目的

自社で給与明細を受け取る一般社員と、自社を管理する社員管理者を登録・変更・削除する機能です。

## 2. 登録・編集項目

| 項目 | 条件 |
|---|---|
| 社員番号 | 必須、50文字以内、自社内で重複不可 |
| ログインID | 必須、ASCIIの英数字・ダッシュ・アンダースコア、50文字以内、全企業で重複不可 |
| 部署 | 任意。選択する場合は自社部署のみ |
| 氏名 | 必須、255文字以内 |
| メール | 必須、メール形式、全企業で重複不可 |
| パスワード | 新規は必須で8文字以上。編集時は空欄なら変更しない |
| パーミッション | 1または9だけ |
| ログイン許可 | 必須の真偽値 |

登録時の会社番号と内部roleは画面から受け取らず、ログイン中の会社番号と`employee`を設定します。

## 3. パーミッション

| 値 | 権限 |
|---:|---|
| 1 | 一般社員。本人の公開済み明細を利用 |
| 9 | 社員管理者。自社管理機能に加え、本人明細も利用 |

社員管理者が自分自身を編集するとき、permissionを1へ下げる操作は拒否します。操作中に管理権限を失うことを防ぐためです。

## 4. 編集時の会社確認

対象社員がログイン中管理者と同じ会社かを確認し、他社社員なら`404`にします。部署の選択肢と入力検査も自社部署だけを許可します。

## 5. パスワードの扱い

新規登録では入力パスワードを安全な形式へ変換して保存します。ただし、画面から新規登録した社員は初回パスワード変更必須には設定されません。

編集時にパスワード欄が空なら、既存のパスワードを維持します。入力した場合は新しい値へ変更しますが、初回変更を必要にする処理はありません。

## 6. 削除・利用停止

削除時は対象に給与明細があるかで処理が変わります。

```text
削除操作
  ↓
自分自身か確認
  ├─ 自分：拒否
  └─ 他の社員
       ↓
    給与明細あり？
      ├─ あり：データを残し、ログインだけ利用停止
      └─ なし：社員を論理削除
```

給与明細がある社員を削除しないのは、過去明細が参照する社員情報を残すためです。

## 7. 注意事項

- 自分自身は削除できませんが、他の社員管理者をpermission 1に変更したり削除したりできます。
- 「最後の社員管理者を残す」件数チェックはありません。自分自身を除く管理者を変更・削除できるため、最終的には操作中の本人だけが残ります。
- 画面登録・編集で設定したパスワードは、仮パスワードとして1回表示される方式ではありません。
- 給与明細を持つ社員は利用停止となり一覧に残りますが、一覧に利用停止列がありません。
- 削除済み社員の復元画面はありません。

## 8. 動作確認の観点

1. permissionは1と9だけ受け付けること。
2. ログインIDとメールが全企業で重複しないこと。
3. 社員番号は自社内だけ重複禁止であること。
4. 他社部署・他社社員を指定すると拒否されること。
5. 自分のpermissionを1へ変更できないこと。
6. 明細あり社員は削除ではなく利用停止になること。
7. 明細なし社員は論理削除されること。
