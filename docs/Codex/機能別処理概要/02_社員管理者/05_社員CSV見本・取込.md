# 社員CSV見本・取込 — 処理概要

## 1. 目的

多数の社員を1人ずつ画面入力せず、CSVファイルでまとめて新規登録・更新する機能です。入力形式を確認できる見本CSVもダウンロードできます。

## 2. 見本CSV

ファイル名は`employees-template.csv`です。UTF-8のBOM付きで、日本語対応表計算ソフトでも開きやすくしています。

```csv
employee_number,login_id,name,email,department_code,permission,password
E001,staff001,山田 太郎,taro@example.test,SALES,1,ChangeMe123!
```

## 3. 列の意味

| 列 | 必須 | 説明 |
|---|:---:|---|
| employee_number | 必須 | 自社内で社員を新規・更新判定する番号 |
| login_id | 任意列 | 空または列なしなら社員番号を使用 |
| name | 必須 | 氏名 |
| email | 必須 | 全企業で重複不可 |
| department_code | 必須 | 自社に登録済みの部署コード |
| permission | 任意列 | 1または9。旧形式列にも対応 |
| password | 新規のみ必須 | 既存社員では値を指定しても現在のパスワードを保持 |

必須見出しとして検査するのは`employee_number`、`name`、`email`、`department_code`です。

## 4. ファイルの基本検査

- ファイル必須
- CSVまたはテキスト形式
- 最大5MB
- UTF-8、SJIS-win、CP932を判定し、UTF-8へ変換
- 先頭行を見出しとして使用
- 完全な空行は無視
- 各値の前後空白を除去

## 5. 行ごとの処理

1. 自社に部署コードが存在するか確認します。
2. 自社内の社員番号で既存社員を検索します。
3. メールが他の社員に使われていないか確認します。
4. 新規社員でパスワードが空ならエラーにします。
5. ログインIDを決め、削除済みも含む全社員との重複を確認します。
6. permissionを1または9へ変換します。
7. 社員番号が既存なら更新、なければ新規登録します。

## 6. 新規と更新の違い

| 項目 | 新規 | 既存更新 |
|---|---|---|
| パスワード | CSV値を保存 | CSV値にかかわらず現在値を維持 |
| 利用可否 | 利用中 | 利用中へ戻す |
| 部署・氏名・メール等 | CSV値 | CSV値で上書き |
| 初回変更 | 明示設定なし | 現在値を維持 |

複数行は1つのトランザクションで処理します。途中の行で業務エラーが起きた場合、前の行も含めて登録・更新を取り消します。

## 7. エラーメッセージ

行のエラーはCSV上の行番号を付けて表示します。例として「3行目: 部署コードが見つかりません。」のように通知します。

主なエラーは次のとおりです。

- 必須列不足
- 部署コードなし
- メール重複
- 新規社員のパスワード不足
- ログインID重複
- permissionが1・9以外

## 8. 旧CSV形式との互換

permissionが空の場合、以前の`is_company_admin`列が真なら9、それ以外は1として扱います。どちらもない場合は一般社員です。

## 9. 現時点での注意事項

- CSV内で同じ社員番号を複数行書いた場合の明示的な重複検査はありません。後の行で上書きされます。
- 既存社員のパスワードをCSVで変更できません。
- CSVのパスワードは8文字以上かを個別検査していません。画面登録より条件が弱い実装です。
- 名前の長さ、社員番号の長さ、メール形式など、画面登録と同じ詳細検査をCSVでは行っていません。DBエラー等になる可能性があります。
- 見出しだけでデータ行がないCSVは0件成功として扱われます。
- 予期しないDBエラーはCSV用メッセージへ変換されない場合があります。

## 10. 動作確認の観点

1. UTF-8とShift-JIS系CSVを読めること。
2. permission 9を社員管理者として登録できること。
3. permission 5などを拒否し全行を取り消すこと。
4. 他社ログインIDとの重複を拒否すること。
5. 既存社員のパスワードが維持されること。
6. エラー行番号が利用者に分かること。
