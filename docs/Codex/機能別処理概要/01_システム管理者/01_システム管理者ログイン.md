# システム管理者ログイン — 処理概要

## 1. この資料の目的

この資料は、システム管理者が専用画面からログインするときに、画面の裏側で何が行われるかを、コードを読まなくても理解できるように説明するものです。

この機能を一言で表すと、次の処理です。

> 入力されたログインIDとパスワードを確認し、利用可能なシステム管理者だけを管理画面へ案内します。失敗が5回続いたアカウントは、安全のためロックします。

## 2. 対象となる利用者

| 項目 | 内容 |
|---|---|
| 対象権限 | システム管理者 |
| ログイン画面 | `/login/manage` |
| ログイン後の主な画面 | 企業一覧 `/manage/companies` |
| 使用するアカウント情報 | システム管理者専用の情報（`admins`テーブル） |

社員管理者と一般社員は、この画面を使用しません。この2権限は共通の `/login` からログインします。

システム管理者のログイン状態と、社員管理者・一般社員のログイン状態は分けて管理されています。そのため、社員用の正しいログインIDとパスワードを入力しても、システム管理者画面にはログインできません。

## 3. 利用者が行う操作

1. ブラウザでシステム管理者専用ログイン画面を開きます。
2. 「ログインID」を入力します。
3. 「パスワード」を入力します。
4. 必要であれば「ログイン状態を保持する」にチェックを付けます。
5. 「ログイン」ボタンを押します。
6. 入力内容とアカウント状態に問題がなければ、企業一覧画面へ移動します。

## 4. 画面の入力項目

| 項目 | 必須 | 入力内容 | システムでの使われ方 |
|---|:---:|---|---|
| ログインID | 必須 | 管理者ごとに発行されたID | 該当するシステム管理者を検索します。 |
| パスワード | 必須 | 管理者本人だけが知っている文字列 | 保存済みパスワードと安全な方式で照合します。 |
| ログイン状態を保持する | 任意 | チェックあり／なし | チェックした場合、ブラウザを閉じた後もログイン状態を復元できるようにします。 |

ログインIDまたはパスワードが空欄の場合は、認証処理へ進まず、入力エラーとして同じ画面へ戻ります。

## 5. 処理の全体像

```text
ログイン画面を表示
        ↓
ログインID・パスワードを送信
        ↓
必須項目が入力されているか確認
        ↓
ログインIDに一致する管理者を検索
        ↓
削除済み・利用停止・ロック中ではないか確認
        ↓
パスワードを照合
        ↓
  ┌──── 一致しない ────┐
  │ 失敗回数を1増やす     │
  │ 5回目ならロックする    │
  │ ログイン画面へ戻る     │
  └──────────────────┘
        ↓ 一致する
ログイン用セッションを新しくする
        ↓
失敗回数を0に戻し、最終ログイン日時を記録
        ↓
初回パスワード変更が必要か確認
        ↓
必要：パスワード変更画面へ
不要：企業一覧画面へ
```

「セッション」は、ログインした本人であることを複数の画面にわたってシステムが覚えておくための情報です。

## 6. 内部処理の詳細

### 6.1 ログイン要求の受付

「ログイン」ボタンを押すと、入力内容が `/login/manage` へ送信されます。

この送信には、別のWebサイトから勝手にログイン操作を実行されにくくするための確認情報（CSRFトークン）が含まれます。確認情報が正しくない要求は受け付けません。

また、ログイン要求は1分間に6回までに制限されています。短時間に大量のパスワードを試す攻撃を抑えるためです。上限を超えた要求は、通常のログイン処理へ進みません。

### 6.2 入力形式の確認

システムは、次の2項目が入力されており、文字列として受け取れていることを確認します。

- ログインID
- パスワード

この段階では、パスワードが正しいかどうかはまだ確認しません。まず、認証に必要な項目が揃っているかだけを確認します。

### 6.3 管理者アカウントの検索

入力されたログインIDを使い、システム管理者専用の保存場所から1人を検索します。

この検索では削除済みのアカウントも確認対象に含めます。これは、削除済みアカウントを誤って通常のアカウントとして扱わないためです。

次のいずれかに該当する場合は、パスワードが合っているかどうかにかかわらずログインを拒否します。

- 入力されたログインIDの管理者が存在しない
- 管理者が削除済みである
- 管理者が利用停止になっている

この場合、画面には「ログインIDまたはパスワードが正しくありません。」と表示します。存在しないID、削除済み、利用停止を画面上で区別しないことで、第三者にアカウントの存在や状態を推測されにくくしています。

### 6.4 ロック状態の確認

該当する管理者がロック中の場合、パスワードの照合は行わず、ログインを拒否します。

画面には「アカウントがロックされています。別のシステム管理者へ連絡してください。」と表示します。

現時点では、一定時間が経過しても自動では解除されません。別のシステム管理者が管理者一覧からロック解除を行う必要があります。

### 6.5 パスワードの照合

アカウントが利用可能でロックもされていない場合、入力されたパスワードと、保存されているパスワードを照合します。

保存されているパスワードは、そのままの文字列ではなく、元の文字列へ簡単に戻せない形に変換されています。システムは入力されたパスワードにも同じ考え方の照合処理を行い、一致するかを判定します。

このログインでは、システム管理者専用の認証方法を使用します。社員管理者・一般社員用のログイン状態とは混在しません。

### 6.6 パスワードが一致しなかった場合

パスワードが一致しない場合は、該当する管理者の連続失敗回数を1増やします。

| パスワード照合前の失敗回数 | 今回失敗後の回数 | 結果 |
|---:|---:|---|
| 0 | 1 | ログイン拒否。再入力できます。 |
| 1 | 2 | ログイン拒否。再入力できます。 |
| 2 | 3 | ログイン拒否。再入力できます。 |
| 3 | 4 | ログイン拒否。再入力できます。 |
| 4 | 5 | ログイン拒否。アカウントをロックします。 |

1回目から4回目までは、「ログインIDまたはパスワードが正しくありません。」と表示します。

5回目の失敗では、失敗回数を5にすると同時にロック状態を有効にし、「ログインに5回失敗したため、アカウントをロックしました。」と表示します。

ロックされた後は、正しいパスワードを入力してもログインできません。

### 6.7 ログインに成功した場合

パスワードが一致した場合、次の処理を行います。

1. システム管理者としてログイン済みの状態にします。
2. ログイン用セッションの識別子を新しくします。
3. 連続失敗回数を0に戻します。
4. 最終ログイン日時を現在日時に更新します。
5. 「ログイン状態を保持する」が選ばれていれば、ログイン状態を復元するための情報を管理します。

セッションの識別子をログイン成功時に新しくするのは、ログイン前の識別子を第三者に知られていた場合でも、その識別子をログイン後に悪用されにくくするためです。

### 6.8 ログイン成功後の移動先

ログイン成功後は、アカウントの「初回パスワード変更が必要」という設定を確認します。

| アカウントの状態 | 移動先 | 理由 |
|---|---|---|
| パスワード変更が必要 | システム管理者用パスワード変更画面 `/manage/password` | 仮パスワードのまま他機能を使用させないためです。 |
| パスワード変更が不要 | 通常は企業一覧 `/manage/companies` | システム管理機能の最初の画面です。 |

ログイン前に別の保護された管理画面を開こうとしていた場合は、パスワード変更が不要であれば、元々開こうとしていた画面が優先されることがあります。

## 7. 結果ごとの画面表示

| 条件 | ログイン可否 | 画面の結果 |
|---|:---:|---|
| 必須項目が空欄 | 不可 | 入力エラーを表示してログイン画面へ戻ります。 |
| ログインIDが存在しない | 不可 | IDまたはパスワードが正しくないと表示します。 |
| 削除済みアカウント | 不可 | IDまたはパスワードが正しくないと表示します。 |
| 利用停止中 | 不可 | IDまたはパスワードが正しくないと表示します。 |
| ロック中 | 不可 | ロック中であることと連絡先を表示します。 |
| パスワード不一致（1～4回目） | 不可 | IDまたはパスワードが正しくないと表示します。 |
| パスワード不一致（5回目） | 不可 | アカウントをロックしたことを表示します。 |
| 認証成功・パスワード変更必要 | 可 | パスワード変更画面へ移動します。 |
| 認証成功・パスワード変更不要 | 可 | 企業一覧、または先に開こうとしていた管理画面へ移動します。 |

エラーでログイン画面へ戻る場合、入力したログインIDは画面に残ります。パスワードは安全のため再表示されません。

## 8. 読み取るデータと更新するデータ

### 8.1 読み取る主なデータ

| データ | 確認する目的 |
|---|---|
| ログインID | 入力に該当する管理者を探すため |
| パスワード | 入力されたパスワードが正しいか確認するため |
| 削除日時 | 削除済みアカウントを拒否するため |
| 利用可否 | 利用停止中のアカウントを拒否するため |
| ロック状態 | ロック中のアカウントを拒否するため |
| 連続失敗回数 | 今回の失敗が何回目か判定するため |
| 初回パスワード変更要否 | ログイン後の移動先を決めるため |

### 8.2 パスワード不一致時に更新するデータ

| データ | 更新内容 |
|---|---|
| 連続失敗回数 | 現在の回数に1を足します。 |
| ロック状態 | 失敗回数が5以上になった場合に「ロック中」へ変更します。 |

### 8.3 ログイン成功時に更新するデータ

| データ | 更新内容 |
|---|---|
| 連続失敗回数 | 0へ戻します。 |
| 最終ログイン日時 | ログインに成功した現在日時を保存します。 |
| ログイン保持用情報 | 「ログイン状態を保持する」が選ばれた場合に利用されます。 |

ログインに成功しても、氏名、ログインID、利用可否などの基本情報は変更しません。

## 9. この機能で行っている安全対策

| 対策 | 分かりやすい説明 |
|---|---|
| 専用ログイン入口 | システム管理者と社員側の認証を分離します。 |
| パスワードの安全な保存 | パスワードをそのまま読める形では保存しません。 |
| 5回失敗時のロック | パスワードを何度も推測する攻撃を抑えます。 |
| 1分間6回の送信制限 | 短時間に大量のログイン要求を送る行為を抑えます。 |
| セッションの再作成 | ログイン前のセッションを悪用される危険を下げます。 |
| CSRF対策 | 外部サイトから本人の意図しない要求を送られる危険を下げます。 |
| あいまいなエラー表示 | IDの存在、削除、利用停止を第三者に推測されにくくします。 |
| 初回パスワード変更の強制 | 発行された仮パスワードを使い続けることを防ぎます。 |

## 10. 現時点での注意事項

- ロックは時間経過では自動解除されません。別のシステム管理者による解除が必要です。
- ログイン画面から行う「パスワードを忘れた場合」の再設定機能はありません。
- 多要素認証（パスワードに加えて確認コードを入力する仕組み）はありません。
- ログイン成功日時は保存されますが、成功・失敗をすべて履歴として残す専用の監査ログ機能はありません。
- ログインIDの前後に誤って空白を入力した場合に、自動で空白を取り除く処理はありません。

## 11. 動作確認の観点

この機能を確認するときは、少なくとも次のケースを試します。

1. 正しいログインIDとパスワードで企業一覧へ移動できること。
2. 初回パスワード変更が必要な管理者は、パスワード変更画面へ移動すること。
3. 存在しないログインIDではログインできないこと。
4. 間違ったパスワードではログインできず、失敗回数が1増えること。
5. 5回連続で失敗するとロックされること。
6. ロック後は、正しいパスワードでもログインできないこと。
7. 利用停止中または削除済みの管理者はログインできないこと。
8. ログイン成功後は失敗回数が0へ戻り、最終ログイン日時が更新されること。
9. 未ログインで管理画面を開くと、システム管理者ログイン画面へ移動すること。
10. 社員管理者・一般社員のアカウントでは、この画面からログインできないこと。

既存の自動テストでは、専用画面からの正常ログイン、ログイン後の企業一覧への移動、未ログインで管理画面を開いた場合の移動先、社員側との認証分離が確認されています。ロック、利用停止、削除済み、入力回数制限などは、今後の自動テスト追加候補です。

## 13. 用語の補足

| 用語 | この資料での意味 |
|---|---|
| 認証 | 入力した人が、登録済みの本人であることを確認する処理です。 |
| セッション | ログイン済みであることを、画面を移動してもシステムが覚えておく仕組みです。 |
| アカウントロック | ログインを一時的に禁止する状態です。このシステムでは管理者による解除が必要です。 |
| 利用停止 | アカウント情報は残しますが、ログインできない状態です。 |
| 削除済み | 画面上では削除されていますが、復元や履歴保持のためデータ自体は残っている状態です。 |
| CSRF対策 | 別のWebサイトから、利用者が意図しない操作を送られる攻撃への対策です。 |
| 認証ガード | どの種類の利用者としてログイン状態を管理するかを分ける仕組みです。 |
