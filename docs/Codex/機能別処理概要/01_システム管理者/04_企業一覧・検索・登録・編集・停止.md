# 企業一覧・検索・登録・編集・停止 — 処理概要

## 1. 目的

給与明細ポータルを利用する企業を管理する機能です。企業の基本情報に加え、新規登録時には最初の社員管理者を同時に作成します。

| 項目 | 内容 |
|---|---|
| 対象 | システム管理者 |
| 一覧URL | `/manage/companies` |
| 主な操作 | 一覧、検索、登録、編集、停止 |

## 2. 一覧と検索

一覧には、新しい企業から順に15件ずつ表示します。

| 表示内容 | 説明 |
|---|---|
| 企業コード・企業名 | 企業を識別する基本情報 |
| 共通ログインURL | 全企業共通の`/login` |
| 利用者数 | 削除されていない所属社員の件数。利用停止中も含む |
| 状態 | 利用中または停止中 |

検索欄に文字を入れると、企業名または企業コードの一部一致で絞り込みます。検索条件はページを移動しても保持します。

## 3. 企業登録の入力項目

| 項目 | 条件 |
|---|---|
| 企業コード | 必須、英数字・ダッシュ・アンダースコア、30文字以内、全体で重複不可 |
| 企業名 | 必須、255文字以内 |
| 代表メール | 任意、メール形式、255文字以内 |
| 電話番号 | 任意、30文字以内 |
| 住所 | 任意、1000文字以内 |
| 利用可否 | 必須 |
| 初期管理者ログインID | 必須、ASCIIの英数字・ダッシュ・アンダースコア、50文字以内、全社員で重複不可 |
| 初期管理者氏名 | 必須、255文字以内 |
| 初期管理者メール | 必須、メール形式、全社員で重複不可 |

## 4. 登録処理

1. 初期社員管理者の入力を確認します。
2. 記号を含まない12文字の仮パスワードを生成します。
3. データベース処理を開始します。
4. 企業情報を検査して登録します。
5. 同じ企業に初期社員管理者を登録します。
6. 両方成功した場合だけ処理を確定します。
7. 一覧へ戻り、仮パスワードを1回だけ表示します。

企業または管理者のどちらかで失敗すると、両方とも登録しません。これを「トランザクション」と呼び、企業だけが残る不完全な状態を防いでいます。

### 初期社員管理者の固定・初期値

| データ | 値 |
|---|---|
| 社員番号 | `ADMIN001` |
| permission | 9（社員管理者） |
| role | employee |
| 初回パスワード変更 | 必要 |
| 利用可否 | 利用中 |

仮パスワードは画面を離れると再表示できません。安全な方法で本人に伝えます。

## 5. 企業編集

編集では企業コード、企業名、代表メール、電話、住所、利用可否を更新します。初期社員管理者の情報は編集対象ではありません。社員管理画面で別途変更します。

企業コードの重複確認では編集中の企業自身を除外します。

## 6. 企業停止

「停止」を実行すると、次を行います。

1. 企業の利用可否を停止へ変更します。
2. 企業を論理削除します。
3. 一覧には表示されなくなります。

社員、部署、給与明細などの関連データをその場で物理削除する処理は行いません。企業を元に戻す画面機能はありません。

## 7. 権限と安全対策

- システム管理者専用の認証が必要です。
- 初回パスワード変更前は利用できません。
- 登録・編集・停止の送信にはCSRF対策があります。
- 企業コード、社員ログインID、メールの重複を防ぎます。

## 8. 現時点での注意事項

- 企業停止では所属社員の`is_active`を変更しません。また、ログイン処理が論理削除済み企業を取得できないことで、所属社員のログインを確実に拒否できない可能性があります。
- 停止済み企業の一覧表示、復元、物理削除機能はありません。
- 企業停止前に給与処理や社員が存在するかを確認する警告以外の業務チェックはありません。
- 初期社員番号は常に`ADMIN001`です。
- 企業編集で利用可否だけを停止にした場合は企業を削除しません。この場合、ログイン処理が企業を取得できるため、所属社員のログインを拒否します。

## 9. 動作確認の観点

1. 企業と初期社員管理者が同時に作られること。
2. 仮パスワードが12文字で1回だけ表示されること。
3. 初期管理者がpermission 9であること。
4. 重複コード、ログインID、メールが拒否されること。
5. 検索と15件ページングが動くこと。
6. 停止後に一覧から消えること。
7. 停止企業の社員ログインについて既知の注意事項を確認すること。
