# 社員管理者・一般社員ログイン — 処理概要

## 1. 目的と対象

会社から発行されたログインIDとパスワードを確認し、社員管理者または一般社員としてシステムへ入る機能です。

| 項目 | 内容 |
|---|---|
| 対象 | 社員管理者（permission 9）、一般社員（permission 1） |
| URL | `/login` |
| 成功後 | ダッシュボード、または先に開こうとしていた画面 |
| 使用する保存先 | `users` |

会社コードの入力はありません。ログインIDは全企業を通して重複しないため、ログインIDだけで所属企業を判別します。

## 2. 入力項目

| 項目 | 必須 | 内容 |
|---|:---:|---|
| ログインID | 必須 | 会社から発行された半角のID |
| パスワード | 必須 | 本人だけが知るパスワード |
| ログイン状態を保持する | 任意 | 次回以降にログイン状態を復元するための指定 |

## 3. 全体の流れ

```text
入力を送信
  ↓
必須項目を確認
  ↓
role=employee かつログインID一致の利用者を検索
  ↓
ロック中か確認
  ↓
パスワードを照合
  ├─ 不一致：失敗回数を増やし、5回以上ならロック
  └─ 一致：ログイン状態を作成
              ↓
          利用者と企業が利用可能か確認
              ↓
          失敗回数を0に戻し最終ログイン日時を保存
              ↓
          初回変更が必要ならパスワード変更画面
          不要ならダッシュボード
```

## 4. 詳細処理

### 4.1 送信回数と不正送信への対策

ログイン送信は1分間6回までです。ログインフォームにはCSRF対策用の確認情報も含まれます。

### 4.2 利用者の検索

削除済みを含む社員情報から、`role=employee`かつログインIDが一致する1人を検索します。permission 1と9は同じ検索対象です。

### 4.3 ロック中の場合

一致した利用者のロック状態が有効なら、パスワード照合をせずに拒否します。「アカウントがロックされています。社員管理者へ連絡してください。」と表示します。

### 4.4 パスワード不一致の場合

存在し、削除されておらず、利用中のアカウントだけ失敗回数を1増やします。5回以上になるとロック状態を有効にします。

システム管理者ログインと異なり、5回目も画面メッセージは「ログインIDまたはパスワードが正しくありません。」です。次回の送信からロック中のメッセージになります。

存在しないID、削除済み、利用停止中のIDでは失敗回数を保存しません。

### 4.5 パスワード一致後の利用可否確認

パスワードが一致すると、まずログイン状態を作成してセッション識別子を新しくします。その後、次を確認します。

- 社員本人が利用中か
- 所属企業を取得できる場合、その企業が利用中か

利用できない場合は、直ちにログアウトさせてセッションを無効にし、「このアカウントは現在利用できません。」と表示します。

### 4.6 成功時の更新

| データ | 更新内容 |
|---|---|
| ログイン失敗回数 | 0に戻す |
| ロック状態 | 解除状態にする |
| 最終ログイン日時 | 現在日時を保存 |
| セッション | 新しい識別子でログイン状態を保存 |

初回パスワード変更が必要なら`/account/password`へ、それ以外はダッシュボードへ移動します。

## 5. 権限別のログイン後

| permission | 表示上の権限 | 使える主な機能 |
|---:|---|---|
| 9 | 社員管理者 | 自社管理機能と本人明細機能 |
| 1 | 一般社員 | ダッシュボード、本人明細、パスワード変更 |

ログイン処理自体は共通で、ログイン後のメニューとアクセス確認で機能を分けます。

## 6. エラーと結果

| 条件 | 結果 |
|---|---|
| 未入力 | 入力エラーで同じ画面へ戻る |
| IDなし・パスワード不一致 | IDまたはパスワードが正しくないと表示 |
| ロック中 | 社員管理者への連絡を案内 |
| 社員が利用停止 | 認証後にログアウトし利用不可を表示 |
| 企業が利用停止 | 企業情報を取得できる場合は認証後にログアウト |
| 成功・初回変更あり | パスワード変更画面へ移動 |
| 成功・初回変更なし | ダッシュボード等へ移動 |

エラー時はログインIDだけを再表示し、パスワードは残しません。

## 7. 現時点での注意事項

- パスワードを忘れた本人がメール等で再設定する機能はありません。社員管理者による再発行が必要です。
- 時間経過による自動ロック解除はありません。
- 多要素認証と専用監査ログはありません。
- 企業が論理削除されると所属企業の関連情報が取得できず、企業の利用停止確認を通過する可能性があります。企業停止時の確実なログイン禁止は修正候補です。
- ロック確認は削除済みかどうかより先に行われるため、削除済みかつロック中のIDではロック中のメッセージが表示されます。

## 8. 動作確認の観点

1. permission 1と9の両方が同じ画面からログインできること。
2. 会社コード入力欄がないこと。
3. 5回の失敗でロックされること。
4. ロック後は正しいパスワードでも拒否されること。
5. 成功時に失敗回数が0になり、最終ログイン日時が入ること。
6. 初回パスワード変更対象は変更画面へ移動すること。
7. システム管理者アカウントではログインできないこと。
