# ログアウト — 処理概要

## 1. 目的

現在のログイン状態を安全に終了し、同じブラウザを使う次の人が前の利用者の画面を開けないようにする機能です。

## 2. 対象と移動先

| 利用者 | 送信先 | ログアウト後 |
|---|---|---|
| システム管理者 | `/manage/logout` | `/login/manage` |
| 社員管理者・一般社員 | `/logout` | `/login` |

画面左側の利用者名の下にある「ログアウト」ボタンから実行します。

## 3. 処理の流れ

```text
ログアウトボタンを押す
  ↓
CSRF確認付きのPOST送信
  ↓
対象の認証からログアウト
  ↓
現在のセッション全体を無効化
  ↓
次回用のCSRFトークンを作り直す
  ↓
対応するログイン画面へ移動
```

## 4. なぜ3つの処理を行うのか

| 処理 | 理由 |
|---|---|
| 認証のログアウト | システムが利用者をログイン済みとして扱わないようにします。 |
| セッションの無効化 | セッション内に残る情報を使用できなくします。 |
| CSRFトークン再生成 | ログアウト前の送信用確認情報を使い回されにくくします。 |

システム管理者は専用の`admin`認証からログアウトし、社員側は通常の`web`認証からログアウトします。

## 5. データへの影響

社員情報、企業情報、給与明細などの業務データは変更しません。ログイン状態を保持するセッションだけを終了します。

ログアウト日時を専用の履歴として保存する処理はありません。

## 6. 注意事項

- 戻るボタンで直前の画面がブラウザ上に一時表示される場合がありますが、再読み込みや操作を行うとログイン画面へ移動します。
- セッション全体を無効にするため、同じブラウザセッション内で複数の認証状態を持たせていた場合は影響を受けます。
- ログアウトはリンクによるGETではなくPOST送信です。外部から勝手にログアウトさせられる危険を下げています。

## 7. 動作確認の観点

1. ログアウト後に保護画面を開けないこと。
2. システム管理者は専用ログイン画面へ戻ること。
3. 社員管理者・一般社員は社員側ログイン画面へ戻ること。
4. ログアウト後に以前のセッション識別子を再利用できないこと。

- `app/Http/Controllers/Admin/LoginController.php`
- `app/Http/Controllers/Auth/LoginController.php`
- `resources/views/layouts/manage.blade.php`
- `resources/views/layouts/app.blade.php`
