# ヘルスチェック — 処理概要

## 1. 目的

Webアプリが応答でき、データベースへ接続できるかを外部から簡単に確認する機能です。ログイン不要で、DockerのWebサービス監視にも使用します。

| 項目 | 内容 |
|---|---|
| URL | `/health` |
| 認証 | 不要 |
| 形式 | JSON |

Laravel自身が用意する`/up`も別に存在しますが、この資料の対象はDB確認を含む`/health`です。

## 2. 正常時

データベースへ`SELECT 1`を送り、成功するとHTTP 200で次の形式を返します。

```json
{
  "status": "ok",
  "app": "アプリケーション名",
  "database": "ok"
}
```

## 3. 異常時

DB接続・SQL実行で例外が起きると、HTTP 503で次を返します。

```json
{
  "status": "error",
  "app": "アプリケーション名",
  "database": "error"
}
```

例外の詳しい内容は応答に含めません。接続先や内部情報を外部へ見せないためです。

## 4. Dockerでの利用

Nginxのコンテナは15秒間隔で内部の`/health`を確認します。連続して失敗するとDocker上でunhealthyと判定されます。

## 5. データへの影響

`SELECT 1`は固定値を返すだけで、企業・社員・給与明細を読み書きしません。

## 6. 注意事項

- メールサーバー、Scheduler、PDFフォント、ディスク空き容量は確認しません。
- 認証不要のためアプリ名とDB接続可否はアクセス者に分かります。
- DBが正常でも、個別のテーブル不整合や業務機能まで正常とは限りません。
- 503時の詳しい原因はアプリ・DBのログを確認します。

## 7. 動作確認の観点

1. DB正常時にHTTP 200と`status: ok`を返すこと。
2. DB停止時にHTTP 503と`database: error`を返すこと。
3. 応答にパスワードや詳細例外を含めないこと。
4. Dockerのhealth状態へ反映されること。

## 8. 主な根拠ファイル

- `app/Http/Controllers/HealthController.php`
- `routes/web.php`
- `docker-compose.yml`
- `bootstrap/app.php`
