# 予約公開・通知メール — 処理概要

## 1. 目的

社員管理者が承認・予約した給与処理を、指定時刻以降に自動で公開し、対象社員へ通知メールを送る機能です。画面操作ではなくSchedulerが毎分実行します。

## 2. 実行方法

`payslips:publish-scheduled`コマンドが毎分実行されます。Docker環境では`scheduler`サービスが`php artisan schedule:work`を動かします。

同じ定期処理が重ならないよう`withoutOverlapping`を設定しています。運用者がコマンドを手動で1回実行することもできます。

## 3. 対象の選択

次を両方満たす給与処理IDを取得します。

- 状態が「承認済み・公開待ち」
- 公開予約日時が現在以前

対象ごとにもう一度データをロックして読み込み、状態と日時を再確認します。複数の処理が同時に同じ給与処理を公開しにくくするためです。

## 4. 公開処理

```text
対象給与処理をロックして再確認
  ↓
状態を公開済みに更新
  ↓
実際の公開日時を現在日時で保存
  ↓ トランザクション確定
社員別明細を1件ずつ通知
```

状態と公開日時を先に確定してからメールを送ります。そのため、メール送信に失敗しても社員はWeb画面で公開済み明細を閲覧できます。

## 5. 通知テンプレート

自社の次の条件に合うテンプレートを、登録の古い順に1件選びます。

- 用途が明細公開
- 使用中

該当がなければシステム既定の件名・本文を使用します。

## 6. 差込情報

| 差込文字 | 値 |
|---|---|
| `{employee_name}` | 社員名 |
| `{target_month}` | 対象月 |
| `{login_url}` | 共通ログインURL |
| `{company_name}` | 会社名 |
| `{department_name}` | 現在の部署名、なければ空 |
| `{login_id}` | ログインID |
| `{payslip_title}` | 給与処理名 |
| `{payment_date}` | 実装上は対象月 |

送信者アドレス指定があればFromへ反映します。

## 7. 送信成功・失敗

社員ごとにメール送信を試みます。

| 結果 | 処理 |
|---|---|
| 成功 | 明細の通知日時`notified_at`を現在日時に更新 |
| 失敗 | 例外をログ報告し、次の社員へ進む。通知日時は空 |

1人の失敗で他社員への送信や給与処理全体を取り消しません。

## 8. 公開後の利用者への影響

- 社員の明細一覧に対象明細が表示される
- 本人が詳細・PDFを利用できる
- 社員管理者の一覧で状態が公開済みになる
- 通知成功件数を給与処理詳細で確認できる

## 9. 現時点での注意事項

- メール送信失敗後の自動再送はありません。給与処理はすでに公開済みのため、次回定期実行の対象外です。
- 企業や社員が現在利用中かを公開前に再確認しません。利用停止中社員や、企業停止後も残っている公開待ち処理が対象になる可能性があります。
- 通知順は明細の取得順で、明示的な並び指定はありません。
- 送信は1件ずつ同期処理のため、社員数が多いと1回の定期処理が長くなります。
- 公開取消・非公開への戻しはありません。
- `withoutOverlapping`のロック有効時間などは既定設定に依存します。

## 10. 動作確認の観点

1. 予約時刻前は公開されないこと。
2. 予約時刻後に公開済み・公開日時へ更新されること。
3. 社員ごとにメールが送られ通知日時が入ること。
4. 送信失敗社員がいても公開状態を維持すること。
5. 二重実行で重複公開・重複通知しにくいこと。
6. テンプレートなしで既定文面を送れること。
