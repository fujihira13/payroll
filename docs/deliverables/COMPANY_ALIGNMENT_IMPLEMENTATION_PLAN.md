# 会社システム寄せ 実装計画・変更記録

文書版: 1.2
作成日: 2026-08-28
根拠: 会社システムの共有チャット、添付画面8枚、現行Laravel実装

## 1. 目的

学習用給与明細ポータルを、会社で使用しているWeb給与明細システムの認証、権限、社員管理、メール管理、帳票設定に近づける。現行のCSV取込、承認、予約公開、PDF、閲覧記録は、会社側に存在しないと確定するまでは削除しない。

## 2. 確定した認証境界

| 入口 | 利用者 | 認証ガード | 保存先 |
|---|---|---|---|
| `/login/manage` | システム管理者 | `admin` | `admins` |
| `/login` | 社員管理者・一般社員 | `web` | `users` |

システム管理者と企業利用者はセッション、ログイン処理、ロック状態を分離する。`/login`利用者は同じ社員アカウントとして保存し、`permission=1`を一般社員、`permission=9`を社員管理者として扱う。

## 3. データ移行方針

追加マイグレーションで次を行う。

1. `admins`を作成する。
2. 既存の`users.role=system_admin`を`admins`へコピーする。
3. 既存の`users.role=company_admin`を`role=employee + permission=9`へ変換し、それ以外の企業利用者は`permission=1`とする。
4. 企業利用者は共通の`/login`で企業コードを入力する。
5. 既存社員のログインIDは社員番号、社員番号がない場合はメールアドレスを初期値にする。
6. 帳票レイアウト、スロット、複数メールテンプレート用の列を追加する。

ロール列は既存データとの互換性のため当面残す。新規企業利用者は`employee`として保存し、企業管理権限は数値パーミッションで判定する。

## 4. 実装フェーズ

### Phase 1: 認証・アカウント基盤

- `admins`モデル、`admin`ガード、`/login/manage`ログイン
- 企業コード・ログインIDによる`/login`
- 5回失敗時のロック
- 初回・リセット後パスワード変更強制
- 管理者と企業利用者のログアウト分離

### Phase 2: システム管理

- 企業一覧と企業共通ログインURL表示
- 企業登録時の初期社員管理者作成
- システム管理者一覧、登録、編集、論理削除
- 12文字仮パスワードの一度だけの表示
- パスワードリセットとロック解除
- 自分自身と最後の管理者の削除防止
- ベース帳票管理

### Phase 3: 企業管理

- 一般社員（permission 1）と社員管理者（permission 9）を同じ社員一覧へ統合
- ログインID、ロック状態、パーミッション値の表示
- 部署名カナ
- 社員の仮パスワード再発行、ロック解除
- テンプレートを選択した社員メール送信
- 社員管理者自身の明細閲覧・パスワード変更

### Phase 4: メール管理

- 複数テンプレート
- テンプレート名、用途、送信者名、送信者アドレス、件名、本文、有効状態
- 会社、部署、社員、ログインID、ログインURL、明細名、支給日の差込

### Phase 5: 帳票設定

- ベース帳票のレイアウト種別
- 帳票項目の初期スロット
- 企業側の3段階ウィザード
  1. ベース帳票選択
  2. 項目・スロット割当
  3. 内容確認
- CSV取込時にスロット情報を明細へ固定保存
- Web・PDFで左右スロットを反映
- 社員管理者による社員別の項目明細表示

## 5. セキュリティ条件

- システム管理者と企業利用者のガードを混在させない。
- 企業管理機能は`permission=9`かつ自社データだけに限定する。
- 仮パスワードはハッシュ化前の値をセッションで1回だけ表示する。
- パスワードリセット時は、初回変更フラグ、ロック、失敗回数を同時に初期化する。
- システム管理者は自分自身と最後の有効管理者を削除できない。
- 社員管理者は自分自身のパーミッションを`1`へ変更・削除できない。

## 6. 検証計画

| 分類 | 主な確認 |
|---|---|
| マイグレーション | 既存3ロールの変換、ログインID重複、既存明細保持、up/down/up |
| 管理者認証 | `/login/manage`成功・失敗・ロック・初回変更 |
| 企業認証 | 企業コード＋ログインID、他社同一ID、ロック |
| 権限 | permission 1の企業管理禁止、permission 9の自社限定、1・9以外の入力拒否 |
| 管理者管理 | 仮パスワード、自分削除禁止、最後の管理者削除禁止 |
| 社員管理 | 管理者フラグ、ロック解除、CSV互換 |
| メール | 複数テンプレート、差込、送信者設定 |
| 帳票 | 3ステップ、スロット保存、CSV、Web・PDF表示 |
| 回帰 | 予約公開、通知、本人明細、閲覧回数、PDF |

## 7. 未確定事項

- 会社システムの正確なロック回数。現時点では5回を採用する。
- 社員管理者が自分の給与明細も持つか。実装は持てる構造とする。
- 会社システムの帳票スロット数・座標。現時点では左右2列の標準／集約レイアウトとする。
- メールテンプレートの選択ルール。明細公開では最初の有効な公開テンプレート、個別送信では画面選択とする。
- 会社側のCSV、予約公開、PDFの有無。現行機能は維持する。

## 8. 完了条件

- `/login/manage`と`/login`が別アカウント・別ガードで動作する。
- 一般社員と社員管理者が社員台帳上のpermission 1・9として管理される。
- 会社画面で確認できた管理者、社員、メール、帳票項目が操作できる。
- 既存の給与公開フローが回帰しない。
- 自動テストと手動画面確認が完了する。

## 9. 実装・検証結果

2026-08-28時点でPhase 1〜5を実装済み。既存機能を削除せず、追加マイグレーションで会社仕様へ移行する構成とした。

| 確認項目 | 結果 |
|---|---|
| マイグレーション | 分離済み`payroll_test`でfresh、追加分down、再upに成功 |
| PHP構文検査 | 変更対象を含む全PHPファイルで成功 |
| ルート生成 | PHP 8.3コンテナで75ルートを生成 |
| 自動テスト | 19件、72アサーション成功 |
| HTTPスモークテスト | `/login/manage`、`/login`、`/health`がHTTP 200 |
| Dockerサービス | app、web、MariaDB、scheduler、Mailpit起動・ヘルスチェック成功 |

自動テストでは、認証ガード分離、permission 1・9の認可と入力制限、5回失敗時ロック、初回パスワード変更、企業登録時の初期管理者作成、一般社員の管理画面拒否、他社社員の操作拒否、帳票3ステップとスロット保存、CSV取込、予約公開、メール通知、本人明細、閲覧記録、PDFを確認した。
