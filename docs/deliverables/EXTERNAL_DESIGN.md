# 給与明細ポータル 外部設計書

> **改訂注意:** この文書は会社システム寄せ実装前の版です。認証・権限・管理者・メール・帳票の最新仕様は、[会社システム寄せ 実装計画・変更記録](./COMPANY_ALIGNMENT_IMPLEMENTATION_PLAN.md)を優先してください。

文書版: 1.0  
作成日: 2026-08-25  
対象: 学習用ローカルWebシステム

## 1. 目的と対象範囲

本システムは、複数会社の給与明細をWebで配布・閲覧するための学習用ポータルです。システム管理者、会社管理者、社員の3権限を分離し、会社間および社員間のデータを隔離します。

対象機能は、会社・利用者・部署・給与明細テンプレートの管理、社員／給与CSV取込、給与明細の承認・予約公開、メール通知、社員本人による閲覧・PDF出力、閲覧状況管理です。

対象外は、給与計算そのもの、勤怠システム連携、銀行振込、年末調整、法定帳票、電子署名、本番バックアップ、監査ログ、パスワード再設定、多要素認証です。

## 2. システム構成

```text
利用者のブラウザ
    ↓ HTTP :8080
Nginx (web)
    ↓ FastCGI
PHP 8.3 / Laravel 11 (app)
    ↓ SQL                         ↓ SMTP
MariaDB 11.4 (db)          Mailpit (開発メール)

Laravel Scheduler (scheduler)
    └─ 毎分、公開時刻を迎えた給与処理を公開・通知
```

| 項目 | 設計 |
|---|---|
| UI | Blade、HTML、CSS、レスポンシブ表示 |
| Web | Nginx 1.27 Alpine |
| アプリ | PHP 8.3、Laravel 11 |
| DB | MariaDB 11.4 |
| PDF | mPDF、IPA/Noto CJKフォント、A4 |
| メール | SMTP。ローカル環境ではMailpit |
| 実行環境 | Docker Compose |
| タイムゾーン／言語 | Asia/Tokyo／日本語 |

## 4. 主要業務フロー

### 4.1 初期設定

```text
専用コマンドでシステム管理者を作成
  → 会社登録
  → 会社管理者登録
  → 共通明細テンプレート登録
  → 会社管理者が部署・社員登録
  → 共通テンプレートを自社設定へコピー
  → 自社用の項目名・順序・有効状態を調整
```

共通テンプレートは原本です。会社設定作成時に項目をコピーし、その後の会社側の変更は原本や他社へ影響させません。

### 4.2 給与公開

```text
給与処理を下書き作成
  → 動的な見本CSVを取得
  → 給与CSV取込・金額計算
  → 会社管理者が内容確認
  → 公開日時を指定して承認
  → Schedulerが公開
  → 社員ごとに通知メール送信
  → 社員が閲覧・PDF出力
  → 会社管理者が閲覧状況確認
```

| 状態 | 値 | 説明 | 許可操作 |
|---|---|---|---|
| 下書き | `draft` | CSV取込・確認中 | CSV取込、承認 |
| 承認済み・公開待ち | `scheduled` | 公開日時待ち | Schedulerによる公開 |
| 公開済み | `published` | 社員が閲覧可能 | 閲覧、PDF、閲覧状況確認 |

## 6. 主要画面仕様

### 6.1 共通

- 未ログインで保護画面へアクセスした場合はログイン画面へ遷移します。
- 全員が同じログイン画面を使用します。認証後は役割別ダッシュボードを表示します。
- 無効な利用者、削除済み利用者、無効な会社に所属する利用者はログインできません。
- ログイン失敗時はメールまたはパスワードのどちらが誤りかを区別しないメッセージを表示します。
- ログインPOSTは1分間6回までです。成功時に失敗回数を0へ戻し、最終ログイン日時を記録します。
- 一覧は原則ページングし、会社・管理者・社員は検索条件を保持します。

### 6.2 会社・会社管理者

| 項目 | ルール |
|---|---|
| 会社コード | 必須、半角英数字・ダッシュ・アンダースコア、30文字以内、全社一意 |
| 会社名 | 必須、255文字以内 |
| 会社メール | 任意、メール形式、255文字以内 |
| 電話番号 | 任意、30文字以内 |
| 住所 | 任意、1000文字以内 |
| 管理者メール | 必須、メール形式、システム全体で一意 |
| 管理者パスワード | 新規必須、8文字以上。編集時空欄なら変更しない |

会社または会社管理者の削除操作は、利用停止にした上で論理削除します。

### 6.3 共通明細テンプレート・自社設定

明細項目は次を持ちます。

| 項目 | ルール |
|---|---|
| 項目コード | 必須、半角英数字・ダッシュ・アンダースコア、60文字以内、設定内一意 |
| 表示名 | 必須、255文字以内 |
| 種別 | `earning`（支給）、`deduction`（控除）、`information`（勤怠・その他） |
| データ型 | `amount`（金額）、`number`（数値）、`text`（文字） |
| 必須 | CSVで空欄を許可するか |
| 有効 | 自社設定でCSV・明細へ使用するか |
| 順序 | 画面上の配列順を保存 |

使用中の共通テンプレートは削除できず、無効化します。共通テンプレート更新は既にコピー済みの会社設定へ反映しません。自社設定を有効にすると、同じ会社の他設定を無効にします。

### 6.4 部署・社員

| 項目 | ルール |
|---|---|
| 部署コード | 必須、30文字以内、同一会社内一意 |
| 部署名 | 必須、255文字以内 |
| 社員番号 | 必須、50文字以内、同一会社内一意 |
| 所属部署 | 任意。指定時は自社部署のみ |
| 氏名 | 必須、255文字以内 |
| メール | 必須、メール形式、システム全体で一意 |
| パスワード | 新規必須、8文字以上。編集時空欄なら変更しない |

所属社員が存在する部署は削除できません。給与明細を持つ社員を削除する場合、過去明細を保持するため物理・論理削除せず利用停止にします。

### 6.5 給与処理

- 作成時は、自社の有効な明細設定、処理名、`YYYY-MM`形式の対象月を指定します。
- CSV取込は下書き状態だけで実行できます。
- 同じ給与処理・社員の明細を再取込すると更新します。
- 給与明細を1件以上取り込むまで承認できません。
- 公開日時は承認時点以降を指定します。
- 承認時に承認者・承認日時を記録します。
- 公開時に状態と公開日時を更新し、その後、社員単位でメールを送信します。
- メール失敗は記録・報告しますが、公開済み状態は取り消しません。

金額計算:

```text
総支給額   = data_type=amount かつ category=earning の合計
控除合計   = data_type=amount かつ category=deduction の合計
差引支給額 = 総支給額 - 控除合計
```

## 7. ファイル・外部インターフェース

### 7.1 社員CSV

```csv
employee_number,name,email,department_code,password
E001,山田 太郎,taro@example.test,SALES,ChangeMe123!
```

- 必須見出し: `employee_number,name,email,department_code`
- 新規社員では`password`必須。既存社員は空欄なら現在のパスワードを保持します。
- 社員番号が同一会社内に存在すれば更新、存在しなければ新規登録します。
- 部署コードは自社に存在する必要があります。

### 7.2 給与CSV

```csv
employee_number,basic_salary,overtime,income_tax
E001,300000,20000,15000
```

- 見出しは`employee_number`と、有効な自社明細項目コードです。
- 必須項目の空欄、数値項目の非数値、存在しない自社社員はエラーです。
- CSVはUTF-8（BOM可）、Shift_JIS／CP932を読み取ります。
- アップロード上限は5MBです。
- 途中行でエラーになった場合、トランザクションによりその取込単位を反映しません。

### 7.3 通知メール

利用可能な差込項目は、少なくとも次を想定します。

- `{company_name}`
- `{employee_name}`
- `{target_month}`
- `{login_url}`

メール本文には給与額やPDFを添付せず、ログインURLを案内します。

### 7.4 PDF

- 対象は公開済みかつログイン社員本人の明細のみです。
- A4、日本語フォントを使用し、ファイル名は`payslip-YYYY-MM.pdf`です。
- PDF出力も閲覧として記録します。

### 7.5 ヘルスチェック

| 項目 | 設計 |
|---|---|
| URL | `GET /health` |
| 正常 | HTTP 200、`status=ok`、`database=ok` |
| DB異常 | HTTP 503、`status=error`、`database=error` |
| 認証 | 不要 |

## 8. 論理データ設計

| テーブル | 主な役割 | 主な制約・関係 |
|---|---|---|
| `companies` | 会社 | `code`全社一意、論理削除 |
| `departments` | 部署 | 会社所属、`company_id + code`一意、論理削除 |
| `users` | 3権限の利用者 | メール全体一意、社員番号は会社内一意、論理削除 |
| `payslip_templates` | 共通テンプレート | 作成者、名称、有効状態 |
| `payslip_template_items` | 共通項目 | テンプレート内コード一意 |
| `company_payslip_settings` | 会社用設定 | 会社、コピー元、設定者、有効状態 |
| `company_payslip_items` | 会社用項目 | 設定内コード一意、元項目参照可 |
| `payroll_batches` | 月次給与処理 | 会社、設定、状態、承認・公開日時 |
| `payslips` | 社員別明細 | 給与処理・社員の組合せ一意、明細JSON、合計、閲覧・通知日時 |
| `email_templates` | 会社別通知文面 | `company_id + type`一意 |
| `sessions` | ログインセッション | 利用者、IP、User-Agent、最終活動日時 |

給与明細の`details`には、作成時点の項目コード、表示名、種別、データ型、値をJSONで保存します。後日テンプレートや会社設定が変わっても、過去明細の表示内容を変えません。

## 9. 非機能・セキュリティ設計

- 認証後にセッションIDを再生成し、ログアウト時にセッションとCSRFトークンを更新します。
- パスワードはLaravelのハッシュ機能で保存し、元の値を表示しません。
- ルートの役割ミドルウェアとControllerの所有会社・本人確認を併用します。
- 会社管理者の検索・更新はログイン利用者の`company_id`で限定します。
- 社員は`published`かつ`employee_id`が本人の明細だけ取得できます。
- DockerのWeb・アプリ・DBにヘルスチェックを設定します。
- Schedulerは毎分実行し、重複起動を抑止します。
- PC・スマートフォン幅で利用できるレスポンシブ画面とします。
- 開発DBと自動テストDBを分離し、テストごとにデータを初期化します。

## 10. 制約・未解決事項

- Laravel 11はセキュリティサポート終了済みのため、本番利用不可です。
- ローカル環境はHTTPであり、HTTPS、Secure Cookie、本番秘密情報管理は未設計です。
- アカウントロック、パスワード再設定、MFA、監査ログは未実装です。
- メールは同期送信です。本番ではキューと外部メールサービスが必要です。
- バックアップ・復元、監視通知、可用性、性能目標、保存期間、個人情報の削除方針は要件確定が必要です。
- 給与CSVの全行置換ではなく、CSVに含まれる社員のみ追加・更新します。取込後の削除機能はありません。
